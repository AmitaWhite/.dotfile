키 목록이 아니라 상황에서 출발한다. 각 워크플로는 "언제 쓰나 → 핵심 키 → 직접 해보기" 순서다. 해보기의 체크는 이 브라우저에 저장되니 nvim 을 옆에 띄우고 하나씩 지워 나가면 된다.

02

파일 · 버퍼 탐색

파일을 열 때 탐색기를 먼저 열지 않는다. 이름을 알면 picker(<leader><space>), 구조를 봐야 하면 탐색기(<leader>e), 방금 봤던 파일이면 최근(<leader>fr).

키동작
<leader><space> / ff프로젝트 루트 기준 파일 찾기 (fuzzy). fF 는 현재 디렉토리 기준
<leader>fggit 이 추적하는 파일만
<leader>fr / fR최근 파일 (전체 / cwd)
<leader>e / E탐색기 (루트 / cwd). 안에서 ? 로 키 목록. a 새 파일, d 삭제, r 이름변경, y/p 복사·붙여넣기, H 숨김 토글
<leader>, / fb열린 버퍼 목록
H / L이전 / 다음 버퍼 (상단 탭줄 순서)
<leader>`직전 버퍼로 토글
<leader>bd / bo현재 버퍼 닫기 / 나머지 전부 닫기 (창은 유지)
<leader>bp / bP버퍼 고정 / 고정 안 된 것 전부 닫기
<leader>fc이 설정 저장소의 파일 찾기
<leader>fp프로젝트 목록
<leader>fn새 파일

해보기탐색기 없이 파일 옮겨 다니기

picker 안에서는 <C-j>/<C-k> 이동, <C-v> 세로분할로 열기, <C-q> 결과 전부를 quickfix 로 보내기.

03

검색 · 치환 · 점프

"이 문자열 어디 있지"는 <leader>/, "커서 아래 단어 어디서 쓰지"는 <leader>sw, 화면 안 저기로 가고 싶다는 s(flash). 여러 파일 치환은 <leader>sr.

키동작
<leader>/ / sg프로젝트 전체 grep (ripgrep). sG 는 cwd
<leader>sw커서 단어(또는 선택)로 grep
<leader>sb현재 버퍼 줄 검색 — 긴 파일에서 / 대신
<leader>sB열린 버퍼들만 grep
<leader>sr검색·치환 (grug-far). 정규식, 파일 필터, 미리보기 후 일괄 적용
<leader>sR직전 picker 다시 열기
s + 두 글자flash — 화면 안 아무 곳으로 점프. 라벨 글자 누르면 이동
Sflash treesitter — 함수/블록 단위 선택
<leader>sj / sm점프 목록 / 마크
<leader>s"레지스터(복사 이력) 보고 붙여넣기
<leader>suundo 트리 — 되돌리기 이력 분기까지
<leader>ss현재 파일 심볼(함수·클래스) 로 점프 (LSP)

04

편집 기술

손으로 타이핑하는 양을 줄이는 도구들. 텍스트 오브젝트(ai ii …), 감싸기(gsa), 주석(gcc), 줄 이동(<M-j>), 자동완성.

키동작
gcc / gc+범위주석 토글 (언어별 주석 기호 자동). gco/gcO 아래/위에 주석 줄 추가
<M-j> / <M-k>줄(또는 선택) 위아래로 이동
gsa + 오브젝트 + 문자감싸기 추가. gsaiw" = 단어를 따옴표로. gsd" 삭제, gsr"' 교체
ai / ii들여쓰기 블록 오브젝트. dii = 같은 들여쓰기 블록 삭제
af / if · ac / ic · aa / ia함수 / 클래스 / 인자 오브젝트 (treesitter). vaf 함수 전체 선택, cia 인자 하나 바꾸기
an / in · al / il다음 / 이전 오브젝트. cin" = 다음 따옴표 안 내용 바꾸기
<C-space>선택을 문법 단위로 점점 넓히기 (treesitter incremental)
<CR> · <C-n>/<C-p>자동완성 수락 · 후보 이동. <C-space> 문서 보기
<Tab> / <S-Tab>스니펫 다음/이전 자리로
<leader>cf포맷 (저장 시 자동 포맷도 켜져 있음, <leader>uf 로 토글)
<leader>.스크래치 버퍼 — 메모나 코드 조각 실험용, 파일 안 만들어도 유지됨

코드 이해 (LSP)

"이거 뭐지 / 어디서 정의됐지 / 누가 쓰지 / 이름 바꾸고 싶다". 언어 서버가 붙어야 동작한다 — 상태줄에 서버 이름이 보이거나 :LspInfo 로 확인. 아래 키는 LSP 가 붙은 버퍼에서만 생긴다.

키동작
Khover — 타입, 문서. 한 번 더 누르면 창 안으로 들어가 스크롤
gd / gD정의 / 선언으로. 돌아오기는 <C-o>
gr참조 목록 (picker)
gI / gy구현 / 타입 정의
gK시그니처 도움말 (insert 에서는 <C-k>)
<leader>ca코드 액션 — import 추가, 자동 수정, 리팩터 제안
<leader>cr심볼 이름 바꾸기 (프로젝트 전체)
<leader>cR파일 이름 바꾸기 + import 경로 갱신 (TS)
<leader>cs / ss심볼 아웃라인 (Trouble 창) / picker
<leader>cS정의·참조 등을 한 창에 (Trouble LSP)
<leader>uhinlay hint 토글 (타입·인자 이름 인라인 표시)
<leader>clLspInfo — 무슨 서버가 붙었나, 왜 안 붙나
<leader>cvPython venv 선택 (pyright 가 그 환경 패키지를 보게)
<leader>cDdocstring 뼈대 생성 (doge) — 함수 위에서

해보기정의 → 참조 → 이름 변경

Python 은 진단이 ruff 만 나온다 (설정 D1). 타입 에러(x: int = "a")는 표시되지 않는다. 필요하면 lua/plugins/lsp.lua 의 ignore 를 지운다.

Java 는 JDK 21 이 PATH 에 있어야 jdtls 가 뜬다 — fish 터미널에서 실행. 첫 프로젝트는 인덱싱에 1~2분.

09

테스트 (neotest)

테스트를 터미널에서 pytest/mvn test 로 돌리고 결과를 눈으로 찾던 것을 에디터 안으로 가져온다. 커서 위치의 테스트 하나만 실행하고, 실패하면 그 줄에 ✗ 와 메시지가 붙는다. 파일 저장할 때마다 자동 재실행(watch)도 된다.

지원: Python(pytest — venv 에 pytest 설치 + <leader>cv 로 venv 선택), Java(JUnit — Maven/Gradle 프로젝트, neotest-java). 다른 언어는 어댑터를 추가해야 한다.

키동작
<leader>ts요약 창 — 파일/클래스/테스트 트리와 결과. 여기서 r 실행, o 출력, i 점프
<leader>tr커서 위치의 테스트 하나 실행 — 가장 많이 쓴다
<leader>tt현재 파일의 테스트 전부
<leader>tT프로젝트 테스트 파일 전부
<leader>tl마지막에 돌린 것 다시
<leader>to / tO실패 출력 float / 아래 패널로 고정
<leader>twwatch — 파일 저장마다 자동 실행 토글
<leader>td커서 테스트를 디버거로 실행 (브레이크포인트 걸어두고)
<leader>tS / ta중단 / 실행 중인 테스트에 attach
]d 등실패는 진단으로도 등록되어 06 의 키가 그대로 통한다

해보기pytest 한 개 → 실패 → 고치기 → watch

요약 창이 비어 있으면 어댑터가 프로젝트를 못 알아본 것이다. Python 은 pytest 가 선택된 venv 에 있어야 하고, Java 는 pom.xml/build.gradle 이 루트에 있어야 한다.

10

디버깅 (DAP)

print 를 세 개 이상 찍고 있다면 브레이크포인트를 건다. 특정 조건일 때만 멈추는 조건부 브레이크포인트(<leader>dB)가 루프 디버깅의 핵심. 어댑터는 mason 이 깔아뒀다: Python debugpy, JS js-debug, Java java-debug, Rust/C codelldb.

키동작
<leader>db / dB브레이크포인트 토글 / 조건부 (i == 42 같은 식 입력)
<leader>dc시작 / 계속. 처음엔 실행 구성(파일 실행, 모듈, attach…)을 고른다
<leader>duDAP UI — 변수·스택·브레이크포인트·REPL 패널 토글
<leader>dO / di / dostep over / into / out
<leader>dC커서 줄까지 실행
<leader>de커서 아래 식(또는 선택) 평가
<leader>drREPL — 멈춘 상태에서 식 입력
<leader>dl / da마지막 구성으로 다시 / 인자 넣어 실행
<leader>dt종료
<leader>td(09) 커서 테스트를 디버거로

해보기루프 안 조건부 정지

"No configuration found" 가 뜨면 그 언어의 dap 어댑터가 없는 것. :Mason 에서 debugpy / codelldb / js-debug-adapter / java-debug-adapter 설치 여부 확인.

11

데이터베이스 (dadbod)

앱 코드 옆에서 "이 쿼리 결과가 뭐지" 를 바로 확인할 때. 접속을 한 번 등록해 두면 <leader>D 로 왼쪽에 DB 트리가 열리고, SQL 버퍼에서 쿼리를 실행하면 아래에 결과가 표로 뜬다. 테이블·컬럼 이름 자동완성도 된다.

dadbod 는 DB 클라이언트 바이너리를 셸로 호출한다 — Postgres 는 psql, MySQL 은 mysql, SQLite 는 sqlite3 가 PATH 에 있어야 한다 (SETUP.md §3).

키 / 명령동작
<leader>DDBUI 트리 토글
:DBUIAddConnection접속 추가. URL 형식: sqlite:///abs/path.db, postgres://user:pw@host:5432/db, mysql://user:pw@host/db
트리에서 <CR>펼치기 / 테이블이면 helper 쿼리(List, Indexes, …) 열기
SQL 버퍼에서 <leader>S쿼리 실행 (선택 영역이 있으면 그 부분만)
<leader>W쿼리를 이름 붙여 저장 (트리의 Saved queries 에 남음)
결과 창에서 <C-]> … 결과 창은 일반 버퍼 — / 검색, yy 복사 그대로

해보기SQLite 파일 하나로 끝까지

접속 정보는 ~/.local/share/nvim/dadbod_ui/connections.json 에 평문으로 남는다. 저장소에 넣지 말고, 운영 DB 비밀번호는 URL 에 쓰지 말 것 (~/.pgpass 등 클라이언트 쪽 인증 사용).
